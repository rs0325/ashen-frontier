# 第1期の生理API（#124）

状態：確定（ユーザー承認 2026-11-26）。係数と出典の正本は[設計14](design/14-m3-climate-survival.md)、睡眠の方針は[設計05](design/05-player.md)。

## 責務と時計

survival → climate/world/core。coreは生理の数値を知らない。新規アイテム・疾病・摂取transaction・気絶救済は追加しない。

`Body` / `Physiology.advance`はMinecraft非依存。温度K、水kg、エネルギーJ、栄養kgを使う。REALで熱・発汗・スタミナ・危険HPを、GAMEで基礎消費・疲労・睡眠・精神・軽傷を計算する。GAMEの食料Jを体熱へ入れない。最大刻み1 REAL秒のRK4。サーバーでは1区間を20 tick以内に絞り、長期間を一度に同期計算しない。

通常20 tickの期限キュー、活動・位置・被弾・跳躍・摂取・深睡眠の境界を記録する。標準のプレイヤーtick通知は境界の検知のみ。全員を毎tick走査して生理計算しない。締切100 µs・最大8小区間で共有EnvironmentBudgetにも従う。継続中の空気入力を凍結した末尾まで評価し、未処理時間を現在時刻へ飛ばさない。

`EnvironmentProvider.exposure(footPosition,from,to)`はC01/C06と同じ確定環境の先頭小区間、風m/s、O2分圧Pa、精度を返す。気象・室内・日長の境界で区切る。屋内の風0.1 m/sは承認済み近似で、換気流速の測定値ではない。降水kg/m²はREALの濡れへ区間で配分する。GAME積算日射J/m²はGAME秒で割ってW/m²へ戻し、REAL熱へ適用する。

未ロード・未計算・未観測の入力は保留。既知のAPPROXIMATEも継続評価する。固定マップの版はclimateが選び、earth_001を編集せず、earth_002未完成を既定値で埋めない。C06は頭部位置を保持登録し、消費済み末尾をCOMMIT、閉じた参照をEND/RELEASEする。保留の旧位置は解決まで保持する。

## 保存と復帰

Attachment `ashen_frontier_survival:physiology` format=2。Bodyの固定順23値と13症状段階、HP/摩耗端数、観測/評価cursor、未精算イベント列、C06の所有UUID・登録番号・位置・末尾、睡眠世代・受領印・最後の返済時刻を同じ保存に含める。必須項目・型・リストの要素型・時刻の連続性が壊れていれば拒否し、空の健康な状態へ置き換えない。未リリース新形式なので移行はない。

ログアウトでは最後のオンライン区間を閉じ、未解決の入力も保存する。再ログインではそのオンライン区間を先に確定し、オフラインの空白だけを生理経過0で通過する。切断で古い危険の端数を消さず、オフライン睡眠・回復・悪化を作らない。respawnのcloneでも状態と受領印を保持する。気絶救済の最低値復帰は別成果。

B2は時間の経過とは別の例外。本人が有効な寝床で100 tickの深睡眠に達した完了候補を保存し、そこまでの実睡眠を確定した後、睡眠負債だけを最大24 GAME時返済する。12 GAME時の間隔はC01日長履歴で元の完了時刻間を計算する。世代ごとに一度だけ受領し、保留・復元・再送・同時刻の再操作で二重適用しない。低酸素の実睡眠区間が後から判明した候補は無効。起きた他人へ返済せず、疲労等の完了ボーナスもない。

## 摂取と効果

`SurvivalIntake.accepted(player,waterKg,energyJ,proteinKg,fatKg,vitaminC,fatSoluble)`は、所有側が確定・重複排除した摂取をサーバースレッドで渡す受け口。未確定の消費・予告・クライアント要求から直接呼ばない。量が不正ならIllegalArgumentException、オンライン状態がなければIllegalStateException。#124の検査では制御fixtureを使い、本番の食品transaction完成と区別する（#125）。

エネルギー20 MJを満腹度20へ表示し、バニラのexhaustion消費とstarvation損傷を生理収支へ二重加算しない。実被弾は防具後の値から負傷へ記録。生理自身のHP適用は被弾として再び負傷へ戻さない。歩行・採掘の低下は最も悪い段階の1係数だけ。設備の自動乾燥・焼成を人の疲労で遅くしない。道具の確定摩耗はcore ToolWearEventで受け、精神の追加摩耗の端数を保存して整数単位で精算する。

`physiologyEffects=false`でも計算と保存を続け、HP・移動・作業・追加摩耗だけを無効化。無効中のHP端数は適用せず精算し、再有効化で後払いしない。

## 同期と検証

`PhysiologyUpdate`は13症状段階、入力保留、効果ON/OFF、息切れだけを本人宛てへ送る。数値計測は端末拡張等の後続成果で、未計測のK/kg/Jを配らない。変更時と20 tickの期限に同期する。最も重い症状を優先し、その原因と対策、無効表示に日英翻訳を持つ。

単体検査：快適・寝床、寒冷・風・濡れ、暑熱・湿度、GAME/REAL分離、脱水/補給、栄養/ビタミン、休息/睡眠/負傷、長区間、独立熱流の細刻み積分128seed×32操作。

GameTest：実ServerPlayerの活動・防具後被弾・跳躍・深睡眠、C01変更、保留を含むAttachment復元、再ログイン、本人だけの同期、OFF。固定seedの保存・同時刻・日長変更・保留再開・補給後保存・ログアウトの実効下限をassertする。実気象/64室/40設備の加工・着火と4人の生理を統合ワークロードで計測する。CPU時間と壁時計を区別して公開資料に記録する。


## 反証後の保存・収支修正（2026-11-26）

NeoForge 21.1.267はAttachmentの読込例外を記録してスキップする。厳格なCODECだけでは初期化を防げないため、登録するserializerは失敗を原文NBT付きの停止状態として保持する。停止状態はBodyを持たず、生理の期限キューへ登録しない。本人へ破損停止を通知し、次の保存も元のTagを保全する。通常の未作成状態と区別する。cloneも同じserializerを通す。管理者の明示的な修復まで自動初期化しない。

format=2は、内部のLease番号とdimension内のC06登録番号を分離し、dimension別の発行末尾を保存する。全Leaseを解放済みのdimensionでも末尾を失わない。未リリースformat=1の試験保存は自動移行せず、上記の停止/原文保全で扱う。試験データの再生成はバックアップ後の明示的な操作に限る。

歩行は移動パケット由来のknownMovementと実位置の変化をサーバーtickで確認する。同じtickの再操作で歩行を消さず、次tickに位置が止まったら古いknownMovementを継続活動へ使わない。

分泌による蒸発放熱は体水分の残高で制約する。枯渇する小区間は水分収支の根を二分探索して分割し、以後の発汗・不感蒸泄/呼吸の潜熱を停止する。基礎GAME消費とREAL超過の二重計上を避けつつ、実分泌量を水分支出の下限とする。通常日長の承認済み基礎予算を変えず、極端に長い日長や熱計算だけのfixtureでも水を無消費で蒸発させない。

OFFではHPの全端数を破棄する。各未精算オンライン区間にも効果ON/OFFを保存し、OFF中の区間がON後に応答しても損傷を持ち越さない。切替境界で区間の合成を止める。

#124の統合性能検査はSurvivalPerformanceGameTestsから実加工workloadを呼び出し、EnvironmentPerformanceGameTestsとcore.testing.ThreadCpuClockの計測/判定をそのまま再利用する。較正は準備前、正のCPU更新16回、最厳閾値の1%以下の分解能ならCPU、粗ければ壁時計を選ぶ。各回500 tick準備＋2000 tick採集でp95<1 ms/p99<3 msを判定する。独自ThreadMXBean・OS名分岐・別の標本配列は持たない。physiology_weather_rooms_stationsの選択時計とCPU/壁時計の値をログに残す。


## 同期処理の削減（2026-11-26）

環境の照会1回の中で、C01の先頭区間を作った室内状態と屋外行を生理入力にも使う。同じ始点の室内再生と屋外履歴の再探索を重ねない。再利用はその呼出し内だけで、次の照会では同tickでも新しい放熱や構成変更を反映する。日長・気象・温度の境界、酸素分圧とAPPROXIMATEの扱いは変えない。

同じ位置・活動・濡れ条件・効果設定・睡眠世代の隣接SPANは、末尾を延長して集約する。未処理の先頭と保持の計数を維持し、イベントや効果切替・睡眠世代の変更をまたいで統合しない。同tickの起床・再就寝でも新しい世代の低酸素をその世代へ記録し、B2返済を拒否する。保存の形式は変わらない。移動速度の生理修正は係数が変わったときだけ付け直し、OFFや症状の回復も同じ係数比較で解除する。通常20 tickの期限、共有100 µs予算、1 REAL秒の計算刻み、本人への変更時/20 tick同期は維持する。
