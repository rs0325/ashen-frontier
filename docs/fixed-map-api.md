# 固定マップの生成契約

Issue #49で追加したworldモジュールの利用方法。設計の正本は[設計12](design/12-m2-fixed-map.md)とする。Block・Item・Fluidの登録はcoreが所有し、worldへ逆依存させない。

## 座標

`io.github.rs0325.ashenfrontier.world.MapCoordinates`を使う。

- `contains(int x, int z)`：両軸とも`[-16384,16384)`の範囲内かを返す。
- `latitude(double z)`：連続ブロックZを北が正の緯度（度）へ変換する。`-80 × Z / 16384`。北端は80、南端境界は−80。丸め・クランプは行わず、範囲外座標も同じ式で換算する。
- `zFromLatitude(double latitude)`：逆変換。北緯40度はZ=−8192。
- `elevation(double y)`：仮想標高m。`(Y−63)×25`。水平距離の圧縮率を適用しない。

`BiomeSource.getNoiseBiome`の入力はquart座標。`QuartPos.toBlock`で絶対ブロック座標へ変換して配置図を読む。地域0〜7、未割当て陸地の緯度帯3種、高山の合計12種を、固定順の`possibleBiomes()`へ列挙する。地下でも同じ水平位置の地表バイオームを使う。

## 版と資産

overworldの`level.getChunkSource().getGenerator()`が`FixedMapChunkGenerator`なら、`mapVersion()`でそのワールドの`MapVersion`を取得する。別生成器からの変換は行わない。`MapVersion`は不変recordで、`mapVersion()`・`formatVersion()`・`manifestHash()`を公開する。

登録IDはChunkGenerator・BiomeSourceともに`ashen_frontier:fixed_map`。MapCodecは各クラスの`CODEC`。生成器のCodecは`map`に`map_version`・`format_version`・`manifest_hash`、`biome_source`に同じ`map`と固定順の`biomes`を保存する。両方の版の不一致は拒否する。未リリースの仮バイオーム形式で作ったワールドは再生成対象で、移行しない。

`BundledMaps.require(MapVersion)`は、クラスパスの`data/ashen_frontier/fixed_map/<map_version>/manifest.json`と資産を照合する。ハッシュはファイルの生バイト列のSHA-256、小文字hex。manifestの`files`は、同じ版ディレクトリからの相対ファイル名とSHA-256の対応。対応形式は1。版が未同梱、形式・ハッシュの不一致、資産の不足・破損では版名を含む例外で停止する。データパックで同梱資産を上書きしない。

現在同梱する`earth_001`は固定シード520026、幅・奥行32768、高さ512、最低Y=−64の配置図。6層の2048² PNG、`index.json`、`geology_profiles.json`を持つ。`BundledMaps.require`はmanifestから必須6層・索引・地質定義の項目が脱落した場合も拒否する。入力・整数対応表・サンプリング・保護域・再生成方法は[制作ツールの契約](../tools/fixed-map/README.md)に記載する。`catalog_version=profiles_001`は整数対応表の版でありcoreの配置カタログ版ではない。

地域図の0は海、1〜7は承認済み地域、255は未割当て陸地。北西大陸本体は全画素を割り当て、南端は西の乾燥地域と東の工業・沿岸工業地帯を延長する。東・南大陸と離れた島嶼には地域を割り当てない。面積比は参考図の輪郭の実測値（北西34.77%、東21.78%、南32.92%、島嶼10.54%）を正とし、凡例の値は使わない。承認済みマスクからの変化を±1ポイントと三大陸の連結で退行検査する。設計12の面積比の記述は別Issueで更新する。

未リリースの`prototype_001`は置き換えたため、その版で作ったワールドは再生成対象。旧形式への移行・既存ワールドの自動更新は行わない。

## 地質と帯水層

索引の`mountains`は制作入力と同じ配列で、固定の主脈north_mainと分岐north_branchを持つ。各範囲のpoints・radius_blocksに従って地質と高さの資産を生成し、Java側の大きな細部振幅もその範囲へ限定する。peak_yは主脈395、分岐375の目安で、実生成の地面は最高395に制限して建築の余地を残す。旧単一mountain形式の互換処理は持たない。承認座標と画像は[設計12の地域配置](design/12-m2-fixed-map.md#地域配置)を参照する。

分岐は2026-11-22のr9で東へ移し、（−3800,−12020）から（−2368,−14992）へ全区間陸上で接続する。旧分岐の島列は独立した山の島へ変更し、入力のトップレベル`mountain_islands`にid・anchor_xz・peak_y、索引の同名配列に画素spans・頂上・内陸距離を出す。島の峰285・235と輪郭は維持し、浜・岩棚を生成せず8ブロックの水際から山の斜面へ直接つなぐ。源流の谷頭・寒冷研究拠点・主脈の峠を保ち、旧分岐の峠を削除してnorth_pathを再導出する。

`walkways`は導出した徒歩経路mining_access・north_pathのidとpoints_x_z_yを持つ。[X,Z,地面Y]を線形補間し、幅8ブロックの路面と外側28ブロックの移行斜面を生成する。入力の拠点高を端点に固定し、主脈と分岐の峠を通る勾配1/8以下の経路とする。地下掘削から保護する半幅8に格子の被覆余裕を加え、粉雪も除外する。旧routesは配置・経路長の契約として引き続き持ち、徒歩の生成高はwalkwaysを参照する。保存済みの旧試作チャンクは更新せず、資産とプリセットのmanifestハッシュを同期して新規ワールドを作る。

`geology.png`の値は同じ版ディレクトリの`geology_profiles.json`の`profiles`を参照する。地質定義の`map_version`・`format_version`を配置図と一致させ、`profile_version`をmanifest/索引の`geology_profile_version`へ記録する。現在の版は`geology_002`。地層は上から順に、母岩Block ID、厚さ範囲、基盤岩、傾斜、断層を定義する。母岩は#50で登録済みの岩石IDかバニラ石材のみ。Dがこの定義から地層を生成し、変位の計算・座標・単位は制作ツールの契約に従う。鉱床の登録ID・母岩・形状・埋蔵量はE（#54）が確定する。

512四方の64×64セルの帯水層と、容量kg・初期量kg・涵養パラメータはF（#55）が担当する。Fが配置図の`map_version`に紐付く版付き資産として追加し、manifestとプリセットのハッシュを同期する予定。Cでは帯水層の値を生成しない。

## SavedDataとの照合

`MapSavedData.verify(ServerLevel overworld, MapVersion expected)`で、初回は照合用記録を作成し、既存記録は完全一致を要求する。戻り値の`mapVersion()`で保存版を参照できる。保存先はoverworldの`data/ashen_frontier_map.dat`。登録イベントが固定マップのoverworldに対して呼ぶため、後続から毎tick呼ぶ必要はない。

サーバーのLevel生成前に既存ファイルも直接照合する。標準SavedDataの破損時の新規作成経路に入る前に停止し、版を置き換えない。生成スレッドはこのSavedDataや可変の研究・気象状態を読まない。

## 起動と後続範囲

専用サーバーはworldとcoreを導入し、`server.properties`へ`level-type=ashen_frontier:fixed_map`を設定する。プリセットに含めるLevelStemはoverworldのみ。シングルプレイは新規作成画面の初回表示で通常プリセットから固定マップへ誘導し、ユーザーの選択変更は維持する。シードが設定済みの再作成画面は誘導しない。既存セーブの読込みは変換しない。

初期ボーダーは中心0、幅32768。Y=−64は岩盤、地表は16bit配置図をCatmull–Romの3次補間で読み、固定シードによる領域の歪みと4オクターブのノイズを加える。オクターブごとに座標を回転し、平野より山地の振幅を大きくする。施設・経路の水平保護域では細部を抑え、その外側96ブロックで滑らかに戻す。代表アンカーの地表高・位置と配置図資産は維持する。

施設の保護半径内は細部振幅を0とし、外側48ブロックの円形の移行域で戻す。経路は細部を完全には消さず通常の25%を残し、配置図由来の等高線の帯を崩す。地下入口は半径12ブロックで振幅を0にし、その外側32ブロックで戻す。これらは生成時の細部の抑制であり、`isProtected`の地下掘削・鉱床の禁止範囲は変更しない。

海岸線からの符号付き距離を1画素の分離カーネルで平滑化し、3次補間と各軸最大6ブロックの歪みで、格子の角をブロック単位の曲線へつなぐ。大陸棚から斜面・深海へ深さを連続させ、低周波と小さな中周波の起伏を海底へ加える。陸側は海面と同じY=63の乾いた砂浜から内陸の斜面へつなぎ、陸64・海底62の固定の段差を作らない。大河は既存索引の中心線を3次曲線へ復元し、ブロック単位の距離から幅64〜96ブロックの河道と谷を彫る。水面は経路に沿って非増加に補間し、海岸へ近づく区間で海面63まで下げる。地域・土壌は同じ連続ノイズで境界の参照位置を歪め、1ブロック単位の乱数で材料を選ばない。`map.region`等の元カテゴリAPIは配置図の最近傍値を維持し、描画するバイオーム・地表材に歪みを適用する。

内陸は最低Y=64、海岸から16ブロック以内の陸側は最低Y=63、海底は水面より1ブロック以上、河床は2ブロック以上低くし、地形上限Y=520により地面上に55、雪層上にも54ブロックの建築余地を残す。土壌図の3種類（肥沃・痩せ・劣化）を地表へ置き、0は母岩を露出させる。水は連続化した水面まで対応するcore流体のsourceを置く。範囲外は空チャンク。`getBaseHeight`・`getBaseColumn`・実チャンクは同じサンプラーを使う。列の補間・ノイズ・地層境界・水域判定はYごとに繰り返さず共有する。バニラの構造物・装飾・初期Mob生成は実行しない。生成アルゴリズムを変更した未リリースの試作ワールドは新規作成し、生成済みチャンクは自動更新しない。

土壌の実際の厚さは20ブロック規模の連続ノイズで2〜4層に変え、地表材と母岩の境界も変化させる。砂浜以外の陸地に32ブロックからの弱い細部ノイズを加え、整数化した段差の幅が規則的に揃わないようにする。表層には2026-11-22承認の`talus`・`river_gravel`・`glacial_till`・`silt`・`loess`・`black_sand`を堆積環境に応じて使う。海底の表層は海岸の種類・深さ・実傾斜で砂、礫、シルト、露岩へ分け、深海は既存の`clay_sediment`とバニラの粘土を使う。削除済みの自然物を復活させない。

`talus_layer`・`silt_layer`・`loess_layer`は地面の上を覆う高さ1〜8の堆積層で、雪層と同じく`surfaceY()`に含めず、`Column.topY()`・base height/column・実チャンクに含める。雪氷・水域・保護域・入口・徒歩路を優先する。ブロックとItemの登録、支持・積層・回収、モデルとタグはcoreの自然物カタログが所有する。新しい材料は列サンプラーの表層選択へ追加し、未使用の登録機構は設けない。

川の水面は中心線に沿う整数Yの水平な淵へ区切る。水位は配置図の上限に加え、河道周囲の彫込み前の標高から安全余裕を引いた上限に合わせ、下流へ非増加にする。源流は幅1〜2・水深1の沢から始まり、蛇行する3本の支沢の合流域で幅と深さを滑らかに増やす。源流から流路距離2,400〜4,200ブロックで既存の中流断面へ移行し、それより下流では連続ノイズによる半幅22〜56・中心水深5〜9を維持する。上流は左右非対称のV字谷、中下流は広い谷と変化する岸の傾斜を持つ。1ブロック下がる位置の前後8ブロックは、川床を最大約1.2ブロックだけ浅くする早瀬とし、源流と支沢は最低1、中下流は最低2ブロックの水深を確保する。水際の岸の上面は実際の水面より高くし、河口の川床も海底へつなぐ。支沢の水質は既存の原水（品質4）。配置図の16ブロック格子は細い実河道の所属判定には使わず、`waterSurface`・`waterQuality`で照会する。水域の静的生成であり、独自の流体tick・水源の補充制御は追加しない。

段差の下流側は同品質の落水（LEVEL=8、非水源）を上流側の水位まで生成し、水源の高さ8/9による河床の細い露出を覆う。`waterSurface`は淵の基準水位であり、段差の落水の上端は`Column.topY()`・`state()`または実チャンクで得る。流れから水源は生成しない。新たな液体tickの一括予約は行わず、既存の流体状態による流れ表示を使う。

陸側の浜幅と海岸の傾斜・移行幅は、背後の高地と固定した露出度から変える。浜・川辺は傾斜と地形条件で砂・砂利・露岩を選ぶ。山が迫る所には陸上の海食崖を作り、海面下は棚へ連続させて垂直な壁を追加しない。

Bはcoreの登録、Cは配置図とmanifest、Dはこの生成器・BiomeSourceの地形と分布を実装する。帯水層はFで追加する。配置図上のspawnはX=−8500、Z=−8192、地表Y=100、床Y=80。初期spawnへの適用とシェルター実体の配置は後続で行う。

## DからE・F・KへのAPI

`FixedMapChunkGenerator.terrain()`は不変の`FixedTerrain`、その`map()`は`FixedMapData`を返す。`FixedMapData.require(MapVersion)`はハッシュを照合し、同じ版のPNGを起動中1回だけデコードする。構築後は配列を変更・公開せず、生成スレッドからSavedDataを読まない。カテゴリは北西角サンプルに対する最近傍（8ブロックの同距離点は東・南側）で、最終画素の範囲内だけ端の値を延長する。

| API | 契約と利用先 |
|---|---|
| `terrain.surfaceY(x,z)` | 地面の基準Y。範囲外−65。地面の上の薄い雪層と水面を含めない |
| `terrain.column(x,z)` | 列ごとの境界を一度計算し、`state(y)`で土壌・雪氷・水込みの生成前地形を返す。`surfaceY()`は地面、`topY()`は地面上の雪層と水面込み。範囲外は全Yが空気 |
| `column.rockState(y)` | E用。土壌・水・雪氷を重ねる前の母岩、底は岩盤。範囲外・地表より上は空気 |
| `map.region(x,z)` | 地域0〜7、255。範囲外0 |
| `map.geologyProfile(x,z)` | E用の地質ID。範囲外0なので`MapCoordinates.contains`と併用 |
| `map.isProtected(x,z)` | E用。施設・経路の水平保護域を16格子で安全側へ被覆し、最大24ブロック広く保護。範囲外false |
| `map.waterMask(x,z)` | F用。連続化した実生成の所属。1=陸側海岸、2=河道、4=湖、8=海。範囲外0。元ラスタとは細部の輪郭が異なる |
| `map.waterSurface(x,z)` | F用。連続化した実生成の水面ブロックY。水域以外・範囲外は`Integer.MIN_VALUE` |
| `map.waterQuality(x,z)` | F用。索引対応表の品質ID、乾燥・範囲外0 |
| `map.soilQuality(x,z)` | F用。混合前の土壌ID、露岩・未割当て・範囲外0 |

地層は`geology_002`の`reference_y`（絶対Y）と、山脈の固定隆起面`uplift`を基準にする。各層の独立した厚さ・尖滅・褶曲・傾斜・断層を加え、現在の列の地表高を使わず層理面を求める。境界は直上の境界以下・Y=−63以上とし、地表は侵食面として層を切る。基盤岩は−127まで、岩盤は−128。固定鉱床中心の母岩接触面は初期化時に求めた絶対Yから接続し、既存の地下の固定Yを保つ。

局所的なうねりを各層の厚さへ入れることで、すべての境界を一緒に動かしたり、同じ上限に押し戻して水平面を作ったりしない。岩盤より上で余裕がある範囲では各層の定義上の最小厚さを確保し、上の層との逆転を防ぐ。

バイオームIDは`ashen_frontier:`名前空間の`polluted_ocean`、`temperate_wasteland`、`abandoned_farmland`、`mining_highlands`、`arid_wasteland`、`industrial_wasteland`、`industrial_coast`、`cold_research_wastes`、`barren_land`、`cold_barren_land`、`warm_barren_land`、`alpine_wastes`。この順でCodecへ保存する。未割当て陸地は絶対緯度60°以上を寒冷、25°未満を温暖、その間を中立にし、高山は地表Y=210を中心に194〜226の移行帯で元のバイオームと混ぜる。

## ワールド端と静的な大気

固定マップのoverworldでは、サーバー起動時に標準WorldBorderの中心を原点、幅を32768に設定する。LevelDataに保存されたスポーンが範囲外なら初期地点`(-8500, 100, -8192)`へ戻し、範囲内なら保持する。ボーダーの同期は標準パケットに任せる。

霧色は各Biomeの標準`effects.fog_color`を使う。標準Biomeには濃度の項目がないため、バイオームIDに対応する補助定義を`data/<namespace>/biome_atmosphere/<biome_path>.json`へ置く。`density`は0〜1の有限数、`dust_particle`は`none`・`ash`・`white_ash`のいずれか。生成元は`tools/fixed-map/write_biomes.py`。追加のライブラリや独自レジストリは使わず、既存の研究定義と同じリロードリスナー・参加時と`/reload`時の全量同期を使う。削除した定義は次の同期で消え、定義のないBiomeは独自描画の対象外となる。砂塵はこの項目で有効にしたバイオームだけに、クライアントの粒子品質設定に従って表示する。

濃度は標準の霧色と同じ4ブロック格子のガウス補間を使う。外縁までの最短水平距離の90%以内で霧を不透明にし、1,024ブロック以内では距離に応じて開始・終了距離をさらに縮める。水・溶岩・粉雪の霧は標準処理を使う。寒冷Biomeの雪片の比率は周囲の気温から補間する。クライアントの粒子品質を無効にしても、距離霧とボーダーは維持する。時刻・天候による濃度変化は追加しない。

高山バイオームは地面Y=194〜226の移行帯を持ち、積雪の下限は緯度・固定ノイズ・斜面の向きと傾斜から別に決める。積雪は雪線の前後16ブロックの移行帯を持ち、地面の上へ`minecraft:snow`の1〜8層を置く。急斜面・岩稜は母岩を露出させる。緩い谷と寒冷研究地域には既存の氷河・氷床を維持し、氷の厚さは緯度・標高と固定した細部から決める。丸める前の実地形のくぼみ・風下・傾斜と水際距離から、吹きだまりの厚さを0〜4の連続量で計算する。厚い所は表層2〜4ブロックを`snow_block`とし、端は薄い雪層へつなぐ。雪層の厚さは地表の連続標高の端数に合わせる。氷河の`packed_ice`・`blue_ice`は積雪の下に置く。

## ブロック汚染（#79）

BlockContamination.get(ServerLevel, BlockPos)は対象の実ブロックについてSoilContamination（6指標）を返し、対象外はOptional.empty。未改変位置はFixedTerrain.Column.contamination(y)を使い、チャンク添付を作らない。必要なら対象チャンクを読み込む。setは対象位置の清浄値を含めた明示値を疎に保存し、対象外はIllegalArgumentException。読取り・更新はサーバースレッドで行う。生成処理では列ごとの6値と深さ減衰を再利用する。

採取・爆発・押し壊し・液体破壊はBlockStateの共通getDrops経路で回収Itemへ反映する。通常のドロップイベントは空いた位置の記録を除去し、爆発・流体への置換もドロップの有無にかかわらず元位置を除去する。設置はNeoForgeの取消し判定後に確定する。導入済みMixinExtrasのWrapMethodを使い、消費前のスタックとオフハンドのコンテキストを保持する。砂・砂利の落下には標準のEntity添付保存を使用し、着地・アイテム化へ引き継ぐ。薄層は同じ濃度だけ積層可能。ECe・pH・MPNを質量分率と混同せず、Cs-137は1アイテムの代表乾燥質量で総Bqと変換する。詳細は設計10・12を参照する。

測定器または既存の損傷した危険区域標識の右クリックで、サーバーの6種類の段階と測定値を英日表示する。標識は直下1ブロックを測定する。高段階の地表表現には既存dead_grassを使い、ブロックの色変更や地図への汚染レイヤーは追加しない。

### 移動・運搬と部分成分（#79 r2）

ピストンは実際のPistonStructureResolverが解決した移動リストから変更前の値を採り、成功後に元位置と移動先の古い記録を除去してから一括転写する。移動中のMOVING_PISTONもチャンクの位置記録で保持し、移動完了・保存後に同じ値を使う。失敗した移動は記録を変更せず、押し壊した位置は回収の有無によらず除去する。

エンダーマンの運搬値は標準の永続Entity添付carried_contaminationに保持する。バニラの持上げ・設置AIと、死亡時の共通ブロックlootへ接続し、運搬可能タグや行動条件は変えない。落下中の保存・着地不能時のアイテム化も同じ代表量を保持する。バニラのディスペンサーには土をブロックとして設置する動作はなく、標準のアイテム排出が成分を保つ。

M1のContamination Codecは部分的なMapを許容するため、lead・pcb・conductivity・ph・fecal_coliformの欠損キーは各清浄値として読む。化学成分なしでCs-137成分だけが存在する場合も、その総Bqを捨てず乾燥基準質量でBq/kgへ戻す。

保存の回帰試験は、保護範囲外の通常チャンクについて管理表とアンロード待ち表からの完全除去を待ち、別のLevelChunkオブジェクトとしてディスクから復元されることを確認する。清浄化後の再アンロード・再読込みと、Overworld/Netherの同一座標の独立性も確認する。試験内の管理表確認は読取りだけで、チャンクを強制的に管理表から除去しない。
