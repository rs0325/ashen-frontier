# 気象セル・イベント・履歴API（#134）

状態: 確定（M3承認 2026-11-25）。[設計14](design/14-m3-climate-survival.md)と[固定気候API](climate-api.md)に従う。#134は全域の数値気象・保存・再構成・周辺同期を実装する。EnvironmentQueryの実提供者、M4、水源・集水・融雪、室内、健康影響、空の描画・観測UIはここに含めない。

## 所有と座標

climate → world/core。MapVersion・FixedClimate.Cell・ClimateProfile・SolarPosition・ClimateClockとcoreのDayLengthHistory/GameTimeを再利用する。追加ライブラリなし。気象数値はMinecraftの型から切り離したWeatherModelで計算する。

64×64、1セル512ブロック。全4096セルを計算し、チャンクのロード状態や参加者数を入力にしない。地形照会・チャンクロードをしない。緯度と仮想標高はworldの既存読取りを使い、気温の位置補正を再加算しない。風の移動には水平距離512 mとREAL秒を使い、25倍の仮想標高縮尺を水平距離へ流用しない。

earth_001は無変更。earth_002は#133と同じ版付き固定層から読む。用途未割当255を新たな産業・農業地域へ割り当てず、物理的な緯度帯と既存の湿潤度で天候候補を選ぶ。酸性雨の発生源は既存の産業地域5/6に限り、D2未配置の産業・水源を補わない。水域inventoryや有限水源の現在量は読まない。

## 状態・単位・境界

WeatherFrameは論理step開始の全域状態。公開後の配列を変更せず、入力面から出力面へ全セルを計算してから交換する。計算順序は結果に影響しない。外周は端セルを反射・保持し、東西端や南北端を循環接続しない。

WeatherStateの主要フィールドは次のとおり。

| フィールド | 単位・意味 |
| --- | --- |
| pressureAnomalyPa | 海面換算の気圧偏差Pa。位置の基準圧力そのものではない |
| temperatureAnomalyK | 基準気候に加えるK偏差。+4 K・標高補正を含めない |
| vaporKgM2 | 大気の水蒸気列の水当量kg/m² |
| windXMps / windZMps | X/Z方向のm/s |
| cloudFraction | 0～1 |
| rainKgM2GameSecond / snowKgM2GameSecond | 雨/雪の水当量kg/(m² GAME秒)。雪を液体集水へ変換しない |
| dustKgM3 / pollutionKgM3 | 粉じん/代表大気汚染のkg/m³。医学的な単一毒性値ではない |
| events / severity | 9イベントのbit集合と代表強度0～1 |

湿潤度は水蒸気列と温度に依存する容量指標から計算する。容量の3～70 kg/m²、10+(T−273.15)という近似はゲーム用で、飽和水蒸気圧の精密式ではない。セル地表温度で雨雪の比率を決め、272.15 K以下は雪、274.15 K以上は雨、その間を線形分離する。

地点の値は4つのセル中心から双線形補間する。端は最端セルを保持する。連続量はセル境界で飛ばず、イベントbitは寄与するセルの集合を保守的に合成する。

通常雨の品質はraw相当、酸性雨イベント中または代表汚染が60×10⁻⁹ kg/m³を超える雨はcontaminated相当。これはゲームの品質分類で、健康影響の閾値ではない。ResourceLocationの水品質や水源への変換は後続が所有する。

## 低次モデルと数値の位置づけ

[NOAAの大循環](https://www.noaa.gov/jetstream/global/global-atmospheric-circulations)と[気団・前線](https://www.noaa.gov/jetstream/synoptic/air-masses)を方向性の根拠にする。中緯度は偏西風、低緯度/極は東風を基準にする。厳密な全球予報・Coriolis方程式・全球エネルギー/水循環の閉じた保存計算は行わない。

次の係数は架空の縮尺世界に対するゲーム調整値であり、出典の観測値ではない。

- 基準風: 中緯度+6 m/s、それ以外−4 m/s。隣接気圧差から0.008の係数で偏差を作り、±45 m/sで制限。
- 気圧の移動する滑らかな波: 振幅1800 Pa、最大偏差±6000 Pa。
- 温度偏差の平常forcing: ±3 K、数値範囲±25 K。
- 4近傍への拡散: 各0.02/30実秒。気候への緩和は水蒸気0.01、それ以外0.04/30実秒。風上移流の重みは各軸0.1以下。
- 水蒸気は降水分を控除した非負の在庫から移流する。年降水量/24ゲーム日を基準にした大気への供給と雨季係数を加える。未解像の蒸発・広域輸送を表す気候入力であり、地表の水源残量を増減する操作ではない。
- 降水率は年降水量と湿潤度に依存し、論理区間内の降水がそのセルの水蒸気在庫を超えないよう制限する。年降水の表は気候の基準値であり、特定の1年の実現値を固定しない。
- 背景粒子: 粉じん5/乾燥地域40 µg/m³、代表汚染8/産業地域80 µg/m³を目標とし、移流・拡散・緩和・降水洗浄を行う。
- 海岸から8192ブロックの湿潤効果、風下の比高1500 mを目安とする乾燥補正、地域の雨季係数を使う。

## 9イベントと初期猶予

seed・GAME日・イベント種別から発生候補、中心、開始/終了を決定する。各日の候補を一様に全域へ置かず、地域・緯度・湿潤度と開始時の温度で選ぶ。有限寿命の移動系に空間的な減衰と時間的なsin²包絡を与える。発生、強化、減衰、終了を同じseedから再構成する。

| 種別 | 候補条件 | 主なforcing/期間のゲーム値 |
| --- | --- | --- |
| 砂嵐 | 乾燥地域または18～32°の乾燥した帯 | 粉じん目標+800 µg/m³、強風、0.5日 |
| 熱波 | 低/中緯度、暖かい季節 | 温度目標+8 K、1.25日 |
| 干ばつ | 乾燥傾向の低/中緯度、暖かい季節 | 水分減少、1.25日 |
| 酸性雨 | 産業/臨海産業 | 汚染目標+200 µg/m³、雨、0.5日 |
| 吹雪 | 高緯度/高地、寒冷時 | 寒冷偏差、雪相、0.5日 |
| 寒波 | 高緯度/高地、寒冷時 | 温度目標−8 K、1.25日 |
| 雷雨 | 暖かく湿潤な低/中緯度 | 雨、低気圧、強風、0.5日 |
| 暴風 | 中/高緯度 | 風偏差、0.5日 |
| 濃霧 | 湿潤な地域 | 湿潤度上昇、0.5日 |

1候補の採用率0.45、半径4～7セル、移動3セル/GAME日などもゲーム値。温度・気圧・粒子のforcingを止めた後は背景へ緩和する。ブロック破壊・落雷火災・地震被害・健康更新はしない。

破壊的な8イベントは開始GAME秒が86400未満なら発生させない。濃霧は猶予中も可能。猶予はワールドのtick=0を原点とする絶対GAME境界86400として保存し、日長履歴を使う。後入り、再接続、同期、再起動で原点を更新しない。

## 降水と日射の積算

降水/降雪は論理区間の率×GAME秒。日射は[NASAの約1361 W/m²という太陽定数](https://data.giss.nasa.gov/modelforce/solar.irradiance/)を参照し、#133のNOAA太陽式から得る。透過率0.75、雲係数1−0.75×雲量、粉じん減衰係数3×10⁶ m³/kgはゲーム近似。

論理区間の中点赤緯を固定し、太陽の正の水平投影だけを解析積分する。日の出/日没を跨ぐ積分を打ち切り、夜は0。赤緯を区間内で一定とする簡略化を明示する。要求の分割点に依存する再サンプリングはせず、同じ原始関数の差で部分区間を求める。雨雪・日射の分割積算は浮動小数の丸め許容差内で一致する。GAME秒の雨・日射を燃料REAL秒のJへ合算しない。

## 履歴・保存・API

保存所有者はWeatherStore、data/ashen_frontier_weather.dat。format=1、weather_model=1、完全なMapVersion、seed、猶予境界、設定履歴、現在/直前フレーム、2冪stepのcheckpoint、進行中イベントを保存する。モデル/マップ版/seed/猶予の不一致や不正な数値を起動前に拒否する。既存の日長履歴はClimateClockだけが正本。

checkpointはstep 0と1,2,4,8…で保持し、全4096セル×全stepを無期限保存しない。longのstep範囲でも64個以内。現在フレームも開始点として利用する。設定変更で同じ境界を再評価するときは直前フレームを優先し、古いcheckpointまで不要に巻き戻さない。

- WeatherQuery.begin(level, position, from, to): 未対応ワールド/範囲外はOptional.empty。負の時刻/逆順/未来は例外。位置Yは気象セルの読取りには使わない。
- WeatherReplay.advance(maximumCells): 1～8192セルの有限仕事量だけ計算。未完了でもカーソルは保持される。この上限はセル数であり実時間の保証ではない。通常のサーバー更新とは別で、呼出し側がtickごとの共通予算内へ分散する。
- page(): 最大128区間のページ。last=falseは全要求が未完了であることを示す。各区間はstart/end、状態、適用設定、雨雪kg/m²、日射J/m²を持つ。部分ページを全要求成功としてEnvironmentQueryへ渡してはならない。
- acknowledge(endTick): ページを所有側の評価へ確定後、その末尾を通知する。次ページが保留中でも、最後に確定した末尾の再通知はそのページを消費せず許可。消費前ページは保存される。
- saveCursor / restoreCursor: 版・seed・モデル、計算済みフレーム、評価済み/確定済みの末尾、未消費ページ、開始時の設定/日長スナップショットを保存/復元する。未完了の1stepだけは最大4096セルの再計算を許す。MapVersion/seed/モデルの不一致を拒否する。未消費ページは確定済み末尾から評価済み末尾まで連続する必要があり、ページの欠落・型不正・区間の隙間や逆転・完了フラグとの不整合は例外で拒否する。空ページは未確定の区間がない場合だけ許可する。同じMapVersion/seedの別ワールドへ移さないことは所有者の前提とする。
- complete(): 最終ページも確定した後にtrue。

保存された設備への適用、ページ消費と設備保存のトランザクション、複数設備の再生仕事の共有は#135の所有範囲。ここでは設備の評価済みtickや水台帳を進めない。

## 設定と通常tickの予算

SERVER設定: weatherIntervalTicks=600（200～600）、dynamicWeather=true、weatherEventsの各種別、weatherCellBudget=2048、weatherBudgetMicros=600。

設定変更は実効tickを記録し、日長変更と同様に論理境界を分割する。初期値は未処理の新しい通知をCASで上書きしない。履歴を遡及して新設定へ変えない。dynamicWeather=falseは明示的な固定気候モードで、基準/季節・卓越風・湿潤度・雲を保ち、動的偏差/降水/イベントを止める。区間と同期にdynamic/有効イベントを含め、未実装の代替providerと混同しない。

通常は1tickあたりceil(4096/interval)+2セルを先行計算し、既定で9セルまで。期限で完成面だけ公開する。周期境界で追いつき用の大きな予算を翌周期へ持ち越さない。遅延・再開時もセル上限と約600 µsの目標期限を、32セル以下の作業片ごとに確認する。OS/GCによる遅延まで保証する値ではない。

## 同期と検証の限界

1実秒ごと、各overworld参加者の所属セルと周囲1セル、最大9セルだけを送る。未ロード地域へは同じ数値更新を続けるが、全域状態を配信しない。版・次元・気象tick・設定も送る。未完成の現在面を送らず、未受信/別次元はクライアントのOptional.empty。切断時はキャッシュを消す。

描画/粒子/UIは追加しないため、開発クライアントは起動しない。周辺選択・codec・キャッシュ・再接続時の状態非リセットを自動確認する。実クライアントの通信経路や見え方は今回未確認で、受信値を使う表示の実装時に確認する。

実測の再生CPU時間、advance回数、圧縮保存量、通常tickのp95/p99は公開引継ぎpublish.mdに記録する。配列から算出する数値領域のサイズ、1呼出し/tickと仮定した待ち時間、4人への通信量は推定として区別する。試験の気象単体p95をM3全体の4人/64室/40設備の予算達成と扱わない。
