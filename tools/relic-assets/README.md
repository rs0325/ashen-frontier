# 遺物アセット

入力は`core/src/main/resources/catalog/relics.json`と、組込みGPT imageで生成した原本4枚。外部配布素材やバニラ画像を使用していない。

| 原本 | 対応プロンプト | 用途 |
|---|---|---|
| `source-atlas.png` | `prompt.txt` | 構成物の材質（8×8セルの最初の8枚） |
| `item-atlas.png` | `item-prompt.txt` | 個別Item50品（8×8セル） |
| `equipment-atlas.png` | `equipment-prompt.txt` | 設備の全面を筐体で埋めた前面32種（8×4セル） |

Pillow 13.0.0（自然物と同じ制作依存）で`generate.py`を実行する。カタログのsprite列は種類ごとの原本セルの0始まり番号。Itemは縮小前にマゼンタのキー色（`min(R,B)-G > 80`）を除去し、透明余白を整えてBOXで16×16へ面積平均、アルファを二値化する。白い布・医療品などの内部は残す。縮小後の全50品の画像ハッシュを照合し、完全一致があれば生成を停止する。

Itemはそれぞれ別の図柄とし、金属くずも形と明確な色差で区別する。構成物のみ同じ材質の形状間で図柄を共有する。窓・扉の規則的な枠抜きはコードで行う。設備は32×32の前面・側面・上面をモデルから参照し、底面は側面材質を使う。側面・上面は原本の筐体色を引き継ぎ、規則的なパネル継ぎ目・ボルト・通気孔を固定乱数で生成する。白い背景やアイコンの貼り付けは使わない。

`preview.png`は全196件を市松背景上に最近傍拡大した目視確認用。`equipment-preview.png`は設備32種の前面・側面・上面を並べた確認用。全50 Itemに78〜198/256の透明画素があり、外周は透明、設備96面はすべて32×32・完全不透明であることをPNGから確認した。再実行に画像生成APIは不要。

```powershell
python tools/relic-assets/generate.py
```

## 劣化建材64件（#156）

確定（ユーザー承認 2026-11-27）。新しいshape付き行はruins-source-atlas.png（8列×5行、40面）とruins-prompt.txtを使用する。spriteはこの原稿の0始まりセルで、旧カタログは旧原稿を参照したまま。原稿は組込みGPT imageの自作画像で外部素材の転載なし。素材の利用はリポジトリのMITに従う。

ruins.pyの指定画素による手調整を既存generate.pyから呼ぶ。セル各辺の内側3%で罫線を除去→BOXで16×16→彩度0.72。健全/風化RCは混入鉄筋を対応する無筋面へ置き直して冷灰色化、ひび/白華/木の割れは固定座標で補正する。窓は二値アルファの枠・反射・ひびに描き直し、実際の欠落はモデル/衝突boxで表す。詳細座標はruins.pyを参照。金属板の穿孔も黒い絵だけにせず固定モデルで穴を空ける。平板と波板は重損傷でも異なる段差を持つ。

再生成は既存と同じpython tools/relic-assets/generate.py。画像生成APIは不要。16px原寸・最近傍拡大・市松・隣接面を確認し、原稿/最終プロンプト/手調整コードを同時保存する。登録/形状/回収は:core:1.21.1:runDataで生成する。モデルの向き/衝突はRuinGeometryとGameTestにより照合する。承認図の原稿プロンプトはruins-proposal-prompts.md、位置/段階の説明正本はdocs/design/16-m2-ruins.md。

ruins-preview.pngは新材64件の原寸16px・4倍拡大・2×2隣接比較を同時に示す。窓は拡大側の市松背景で二値アルファを確認する。実ゲームの描画/選択の見え方とは区別する。

鉄骨・平鋼板・波板は段階ごとに原稿セル20〜23を共有し、モデルはintact/weathered/pitted/section_loss_steel_beamの4画像へ直接参照する。板IDごとのPNGは制作対応表用の同一画像で、描画元の別材質にはしない。原稿の36〜39は保存するが製品画像には使用しない。

窓の正面・裏面は通常UV、厚み方向の端面は同じ画像の不透明な枠画素UV [0,0,1,1]を参照する。4種類×水平4方向をRuinModelTestで検査する。外部に露出する同方向の面を1px角で照合し、共面の重複を検出する検査も行う。形状の和集合一致とは別の検査である。
