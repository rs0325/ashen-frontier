# 固定マップ制作ツール

Python 3.12、NumPy 2.2.6、Pillow 11.2.1を使う制作専用ツール。ゲームから呼び出さず、Modの依存には追加しない。設計の正本は[設計12](../../docs/design/12-m2-fixed-map.md)、Java側の入口は[固定マップ契約](../../docs/fixed-map-api.md)。

## 環境と実行

リポジトリルートで実行する。以下のコマンドも作業環境の`run_logged.py`で記録する。作業環境の共通Pythonは記録用であり、制作環境はPython 3.12を使う。

```powershell
py -3.12 -m venv tools/fixed-map/.venv
& .\tools\fixed-map\.venv\Scripts\python.exe -m pip install --require-hashes -r tools/fixed-map/requirements.txt
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/generate.py --update-preset --preview tools/fixed-map/preview/earth_001.png
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tools/fixed-map -v
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/generate.py --validate
.\gradlew.bat build
.\gradlew.bat gameTest
```

バイオームと英日表示の生成は標準ライブラリのみの`python write_biomes.py`で行う（リポジトリルートからは`tools/fixed-map/write_biomes.py`）。出力JSONはGitで管理する。配置図の`--update-preset`は生成器とバイオーム両方の版・manifestハッシュを同期する。

地下配置は`write_underground.py`の固定定義を共通入力にし、通常の`generate.py`が`underground.json`を同梱・ハッシュ照合する。地下だけを調整したときは`python tools/fixed-map/write_underground.py`で地下資産・制作スクリプトのハッシュ・プリセットを更新できる。配置図全体の再生成比較には、上記の固定依存環境を使う。

必須資源は`index.json`のアンカーIDに対応する。アンカーは候補範囲を表し、実際の位置・形状・母岩・深さは地下資産を参照する。施設保護域を掘削せず、`spaces`に施設ID付きの外部接続口と経路を保持する。レンズ込みの母岩、入口の解釈、F・Iへの引継ぎは[地下生成の契約](../../docs/fixed-map-api.md#eの鉱床と地下経路)を正本とする。

POSIXでは仮想環境の実行ファイルを`.venv/bin/python`へ読み替える。同じPythonのマイナーバージョン、固定ライブラリ、入力、ツールで再生成する。標準`unittest`を使うためテスト依存は不要。生成処理は約10秒、配列と排水ヒープを含む一時メモリは数百MiB規模を想定する。制作時だけの一括処理でありゲームのtick処理には持ち込まない。

`--input <directory>`は相対・絶対パスを受け取り、最初に絶対パスへ解決する。manifestの`inputs`は入力ディレクトリからの相対名とハッシュを記録する。`--output <directory>`で比較用の別出力を作れる。省略時は入力の`map_version`を同梱先のディレクトリ名に使い、検査もその版に照合する。次版の入力でも同じCLIを利用できる。

出力は同じ親ディレクトリ内の一時領域で生成・検査してから一式を置き換える。生成失敗では旧出力を変更せず、通常の置換失敗では旧出力へ戻す。生成資産以外がある出力先は拒否する。復旧自体が失敗した場合は旧出力を含む一時領域を保全する。強制終了や同時読取りに対する二つのrenameの一括原子性は提供しないため、制作中は同じ出力を使うゲーム・ビルドを並行実行しない。

通常の再生成は入力PNGを読み、参考図の再抽出は行わない。`--update-preset`を指定した場合だけworldプリセットの版とmanifestハッシュを同期する。プレビューと仮想環境は`.gitignore`で除外している。PNGとJSONは通常のGit対象とする。

## 入力の編集と由来

- `input/land.png`: 2048²の8bitラベルPNG。0=海、1=北西大陸、2=東大陸、3=南大陸、4=島嶼。色補正せず整数値で編集する。
- `input/extraction.json`: 参考図のパス、原本SHA-256、切出し座標、縮尺、抽出設定。
- `input/layout.json`: 地域ポリゴン、山脈、大河、固定シード、施設代表アンカー、経路、鉱床アンカー、未決定事項。座標はブロックX/Z。
- `input/corrections.json`: 原図のピクセル座標による手修正と、陸海の照合点。北西大陸の氷河の青い影を陸へ戻した範囲を記録する。
- `input/geology.json`: 地質プロファイルの版、上下の地層、母岩、厚さ範囲、傾斜・断層、参照した#50カタログのcommit/原本SHA-256。

参考図の±18,000ラベルは36,000四方の指定として扱う。図中の目盛文字は海岸の張出しより内側にあり、以前の画像X=294〜1160、Y=67〜916による切出しでは西の海と東大陸の一部を切っていた。修正後は海岸と外周の海を含む作図範囲X=256〜1212、Y=27〜930を32,768四方へ対応させる（32768/36000倍）。目盛文字の配置を正確なピクセル座標の基準には使わない。北は−Z、上端80°N、下端境界80°S。図の縦横差はそれぞれ2048pxへ対応させて補正する。この切出し変更も未リリース版の再生成対象。

参考図からやり直す場合だけ次を実行する。**手修正した入力PNGは上書きされる。**

```powershell
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/extract_mask.py
```

濃紺の海（B−R>20、B−G>6、R<80）を基準に分類し、赤い火山地形を陸として保持する。海上の文字・凡例箱・宇宙ステーション挿絵・破線・座標線は局所的に除外する。3pxのclosingとmedian、12px未満の小領域除去を行い、海峡を大きなフィルタで埋めない。閉じた内陸の穴は、地名・地形描き込みを採用しない陸海輪郭として埋める。内陸湖を参考図から引き継ぐ操作ではない。海に誤検出された内側の氷河の影だけを`corrections.json`の手描きポリゴンで戻す。除外した文字等の矩形と経路は`extraction.json`にも記録する。

`preview/reference-overlay.png`は原図に入力マスクを重ね、抽出した輪郭を桃色で示す。`preview/reference-comparison.png`は左から原図・ラベル図・重ね合わせ。これらと`preview/mask.png`を目視照合してから生成する。大陸は位置と連結成分から識別し、残る島を4へまとめる。個別の島の役割は決めない。

面積比は参考図の輪郭から実測した北西34.77%、東21.78%、南32.92%、島嶼10.54%を採用し、凡例の38/27/21/14%は使わない。承認済みマスクの記録値を`layout.json`の`area_ratio_reference`に保持し、±1ポイントの退行検査と三大陸の連結検査で輪郭の変化を検出する。実測値は`index.json`の`metrics`にも記録する。設計12の面積比の記述は別Issueで実測値に合わせるため、ここでは変更しない。

## 生成とデータ形式

標高ノイズ（固定PCG64）→東西山脈→海岸の遷移→河床の制約とpriority floodによる窪地処理・集水方向/面積→地質→土壌/水域→施設/経路索引、の順に処理する。全面的な侵食シミュレーションは行わない。施設のアンカー高と周囲128ブロックの移行斜面は排水解析の前提に含め、保護域と水域の重複を拒否する。

地域ポリゴンは承認緯度帯の包絡であり、その長方形を出力境界にはしない。山脈線・平滑標高・固定ノイズで座標を曲げ、農業域は大河沿い、乾燥/工業の境界は入力の分水界と標高、沿岸域は海岸から640ブロック以内を参照して形を決める。IDの形を変えるだけであり、128〜256ブロックの境界の連続化はDの担当。

大河は制約点を通るCatmull–Rom曲線に固定シードの蛇行（最大180ブロック）を加え、河床の周囲に谷を作る。水面は経路長に沿って海へ非増加となる。経路は64ブロック格子のA*で海と高度差を避け、角を二次曲線で丸める。出力索引には入力の直線ではなく、この地形を参照した折れ線を保持する。

出力先は`modules/world/src/main/resources/data/ashen_frontier/fixed_map/earth_001/`。

| ファイル | 値 |
|---|---|
| `height.png` | 16bit grayscale。0〜383をY=−64〜319へ対応 |
| `region.png` | 8bit。0=海、1〜7=承認済み地域、255=未割当て陸地 |
| `water.png` | 8bit。0=乾燥、1〜8=水質。対応表は索引 |
| `soil.png` | 8bit。0=露岩・未割当て、1〜5=肥沃/貧栄養/劣化/汚染/有毒 |
| `geology.png` | 8bit。0=海、1=未分類陸地、2〜5=平野/山脈/乾燥/沿岸プロファイル |
| `coast_river.png` | 8bit。bit 1=陸側海岸、2=河道、4=湖、8=海。初版に湖はない |
| `index.json` | 整数対応表、水域の水面高、施設/保護域、経路、鉱床アンカー、実測値 |
| `geology_profiles.json` | `geology.png`の値を解決する版付きの地層定義 |
| `manifest.json` | 版、形式、固定シード、寸法、入力とツールのハッシュ、依存版、全成果物ハッシュ |

地域1=初期生存、2=旧農業、3=鉱業、4=内陸乾燥、5=工業、6=沿岸工業、7=寒冷研究（北）。日英名は索引の`tables.region`に保持する。北西大陸本体は全画素を割り当て、南端は西側の乾燥地域と東側の工業・沿岸工業地帯を延長する。東・南大陸と離れた島嶼は255。地熱・宇宙開発・南の寒冷地域は生成しない。東・南大陸と島は地形と海岸だけを持ち、土壌や淡水の地域配分を先取りしない。

原点は北西端`(-16384,-16384)`、1px=16ブロック。`px=floor((x+16384)/16)`、`py=floor((z+16384)/16)`。ラスタ値は各セル北西角のサンプル。Dは標高を隣接セルと共有の補間で読み、カテゴリは最近傍で読む。範囲外はラスタをクランプして地形にせず、既存の空チャンク境界処理へ渡す。

水面表の`surface_spans_y_x0_x1ex_y`は`[行,開始列,終了列（排他的）,水面Y]`。海はbit 8のセルすべてで水面63、大河はbit 2のセルに対する表を持つ。水質は`water.png`を優先する。河床は水面より低く、中心線の水面は海に向かって非増加となる。大河以外の網状河川や湖の追加はこの初版の対象に含めない。

施設は代表アンカーと水平保護半径を渡す。`surface_y`は地表のブロックY、spawnの`floor_y`は地下シェルター床のブロックY。テンプレート寸法と上下の保護範囲はI/Jで確定するまで、Dはこの水平円柱内の地下掘削・鉱床・細部ノイズを抑える。経路は折れ線と保護幅を渡す。`length_blocks`は平面折れ線長であり、歩行所要時間や実際の段差込み距離ではない。車両用の線路状態・勾配設計はM7で行う。

鉱床は8資源の`anchor_only`を渡す。`resource`は資源分類、`geology_profile`は地質図との照合用整数。登録ブロックID・鉱物と母岩の組合せ・形状・埋蔵量はE（#54）の`underground.json`で定義する。`radius_blocks`は候補位置の範囲であり、このアンカー資産だけでゲーム内鉱床が完成したとは扱わない。ユーザーの決定に従い、地下資産には噴気帯の単体硫黄と黄鉄鉱を両方少量ずつ配置する。どちらを序盤で必須の入手経路にするかはM4（Tier 0）の設計で決める。

### 地質プロファイルとDへの契約

`geology_profiles.json`は`map_version`、`format_version=1`、`profile_version=geology_001`を持ち、manifestと索引の`geology_profile_version`に一致させる。`profiles`のキー0〜5が`geology.png`の値。全ファイルを同じmanifestのSHA-256照合対象にする。

各プロファイルは`layers_top_to_bottom`の順に地層を持ち、各層の`id`、`rock`（名前空間付きの母岩Block ID）、`thickness_blocks=[最小,最大]`を読む。厚さは整数ブロックで両端を含み、Dはマップ固定シード・`thickness_salt`・プロファイル/地層ID・絶対座標から範囲内の値を決める。ワールドシードや探索順を混ぜない。土壌は地質列の上部へ後段で適用する。

列の上端を`height.png`の地表Yとし、地層境界は上端から厚さを累積して引く。`dip`の`anchor_xz`を原点とする座標差と`gradient_xz`の内積を、各境界のY変位として加える。傾斜はブロック/ブロックの無次元値。`faults`は`point_xz`を通る鉛直面で、`normal_xz`との内積が0以上の側に`throw_blocks`の変位を加える。変位は下部境界だけに適用し、各境界を直前の上端以下、`bottom_y=-63`以上に制限する。最後の境界より下は`basement`で埋め、Y=−64は別途岩盤とする。Dはこの定義を読んで地層を生成する。

山脈は花崗岩・片麻岩・珪岩、平野/流域は粘土質堆積物・砂岩・頁岩・石灰岩、乾燥域は粘土質の表層と砂岩・石膏・岩塩、沿岸は堆積岩の層を持つ。未割当て陸地/海底は地域の役割を付けない汎用の石基盤とする。層順・厚さ・傾斜・断層は架空地形の制作値であり、実在の地層の復元値ではない。

母岩IDは#50の`docs/nature-catalog.md`と`core/src/main/resources/catalog/nature.json`（参照commit/ハッシュは入力に記録）の岩石とバニラ石材だけを使う。地質的な関係の既存参照は同カタログの`banded_iron`、`silica`、`carbonate_zinc`、`nitrate`の範囲とする。鉱床の母岩選定はE（#54）の責務であり、Cの地層順序から鉱物の存在を推定しない。

### 帯水層の後続契約

512四方・64×64セルの帯水層について、容量kg・初期量kg・涵養パラメータはF（#55）が配置図の`map_version`とmanifestに紐付く版付き資産として追加する。Cでは帯水層の値を作らない。Fが資産を追加したときはmanifestとプリセットのハッシュも同期する。

`catalog_version=profiles_001`はこの整数対応表の版であり、#50のcore配置カタログ版ではない。既存のcoreの登録を変更しない。未リリースの`prototype_001`を置き換えたため、仮版ワールドは再生成対象。自動移行は追加しない。

## 検査・反証

単体テストは寸法・型・全画素の値域と未割当て、面積比、隣接、原図の陸海照合点、西端の海、三大陸の連結、境界形状、蛇行と谷、施設の距離と地表高、鉄道/徒歩経路、全河道セルの海への接続、水面高、排水木と集水面積、相対入力による再生成ハッシュ、別版のCLI生成/検査/プリセット更新、生成・置換失敗時の旧出力保全、地質の参照/版/厚さ、版不一致、manifestからのレイヤー脱落、実ファイル欠落/破損、不正入力値を検査する。worldのGameTestは6層をJava ImageIOで読み、同梱版・寸法・ビット幅も確認する。

`generate.py --validate`は版・形式・必須ファイル・ハッシュ・PNGの寸法と型を検査する。面積比や地域接続の制作検査は単体テストで行う。ファイル更新後は`--update-preset`付きで再生成し、必須検証を再実行する。

GameTestの実行用ワールドは`modules/world/versions/1.21.1/run/world/`に残る。manifest更新後に旧ハッシュとのSavedData不一致で失敗した場合は、この作業で生成したテスト用の`data/ashen_frontier_map.dat`を`preview/`等へ保全してから再実行する。今回もこの経路で旧版停止を確認した。実際のプレイワールドは自動更新せず新規作成する。
