# 固定マップ制作ツール

Python 3.12、NumPy 2.2.6、Pillow 11.2.1を使う制作専用ツール。ゲームから呼び出さず、Modの依存には追加しない。設計の正本は[設計12](../../docs/design/12-m2-fixed-map.md)、Java側の入口は[固定マップ契約](../../docs/fixed-map-api.md)。

## 環境と実行

リポジトリルートで実行する。以下のコマンドも作業環境の`run_logged.py`で記録する。作業環境の共通Pythonは記録用であり、制作環境はPython 3.12を使う。

```powershell
py -3.12 -m venv tools/fixed-map/.venv
& .\tools\fixed-map\.venv\Scripts\python.exe -m pip install --require-hashes -r tools/fixed-map/requirements.txt
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/generate.py --update-preset --preview tools/fixed-map/preview/earth_001.png
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tools/fixed-map -v
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/generate.py --validate
.\gradlew.bat build
.\gradlew.bat gameTest
```

バイオームと英日表示の生成は標準ライブラリのみの`python write_biomes.py`で行う（リポジトリルートからは`tools/fixed-map/write_biomes.py`）。出力JSONはGitで管理する。配置図の`--update-preset`は生成器とバイオーム両方の版・manifestハッシュを同期する。

地下配置は`write_underground.py`の固定定義を共通入力にし、通常の`generate.py`が`underground.json`を同梱・ハッシュ照合する。地下だけを調整したときは`python tools/fixed-map/write_underground.py`で地下資産・制作スクリプトのハッシュ・プリセットを更新できる。配置図全体の再生成比較には、上記の固定依存環境を使う。

必須資源は`index.json`のアンカーIDに対応する。アンカーは候補範囲を表し、実際の位置・形状・母岩・深さは地下資産を参照する。施設保護域を掘削せず、`spaces`に施設ID付きの外部接続口と経路を保持する。レンズ込みの母岩、入口の解釈、F・Iへの引継ぎは[地下生成の契約](../../docs/fixed-map-api.md#eの鉱床と地下経路)を正本とする。

POSIXでは仮想環境の実行ファイルを`.venv/bin/python`へ読み替える。同じPythonのマイナーバージョン、固定ライブラリ、入力、ツールで再生成する。標準`unittest`を使うためテスト依存は不要。生成処理は検証環境で数分程度、配列と排水ヒープを含む一時メモリは数百MiB規模を想定する。制作時だけの一括処理でありゲームのtick処理には持ち込まない。

`--input <directory>`は相対・絶対パスを受け取り、最初に絶対パスへ解決する。manifestの`inputs`は入力ディレクトリからの相対名とハッシュを記録する。`--output <directory>`で比較用の別出力を作れる。省略時は入力の`map_version`を同梱先のディレクトリ名に使い、検査もその版に照合する。次版の入力でも同じCLIを利用できる。

出力は同じ親ディレクトリ内の一時領域で生成・検査してから一式を置き換える。生成失敗では旧出力を変更せず、通常の置換失敗では旧出力へ戻す。生成資産以外がある出力先は拒否する。復旧自体が失敗した場合は旧出力を含む一時領域を保全する。強制終了や同時読取りに対する二つのrenameの一括原子性は提供しないため、制作中は同じ出力を使うゲーム・ビルドを並行実行しない。

通常の再生成は入力PNGを読み、参考図の再抽出は行わない。`--update-preset`を指定した場合だけworldプリセットの版とmanifestハッシュを同期する。プレビューと仮想環境は`.gitignore`で除外している。PNGとJSONは通常のGit対象とする。

## 実地形の全体図

ユーザーから現状の全体図を求められたとき、バイオーム・地形配置の案を作るとき、大規模な地形変更の確認・比較に使う。Claude Codeでは[fixed-map-renderスキル](../../.claude/skills/fixed-map-render/SKILL.md)にも同じ入口を記載している。Codexも以下を直接利用できる。

上記のPython 3.12仮想環境とハッシュ固定依存を使い、対象worktreeのルートで実行する。適用される`run_logged.py`でコマンド全体を記録する。

```powershell
# 全域16ブロック/画素＋北西大陸8ブロック/画素、詳細版と淡い版の計4枚
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/render_map.py

# 全域または北西だけ（省略時の間隔はworld=16、northwest=8）
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/render_map.py --preset world --step 16
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/render_map.py --preset northwest --step 8

# 任意範囲: X0 Z0 X1 Z1。上限を含まず、各辺がstepで割り切れること
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/render_map.py --bounds -6000 -15000 -2000 -11000 --step 8
```

出力先は省略時`preview/maps/<日時>-<commit>/`。`--output <新規または空のディレクトリ>`で変更できる。リポジトリ内ではignoredの場所だけを受け付け、既存ファイルのある出力先を上書きしない。`--font <日本語フォントのttf/otf/ttc>`でフォントを指定できる。Windowsの游ゴシック、LinuxのNoto Sans CJKの標準パスを自動検出する。POSIXでは`.venv/bin/python`へ読み替える。

専用initスクリプト`map-render.init.gradle`が開発用ソースセットと`runFixedMapRender`をその実行だけに追加する。Javaの`FixedTerrain.column`でセル中心の地面Y・最上面Y・地表材・水面材を標本化し、地表・水面・雪氷を判定する。配置図の高さPNGだけでは描かない。専用GameTest名前空間・テンプレートと`build/map-render-run`を使い、通常のGameTestを走らせず、配布jar・通常の`runClient`・`gameTest`の登録や結果を変えない。実行後は単発Gradleデーモンも終了する。開発クライアントは起動しない。同じworktreeで他のGradle実行・編集と重ねない。

詳細版`*-detail.png`は標高段彩、北西からの陰影、海底の水深、水域、雪氷、施設アンカー名、配置上の山脈軸と固定峰を表示する。描き込み版`*-sketch.png`は同じ範囲・座標格子を持つ淡い図。1000ブロックごとの格子、北が上・X東・Z南、縮尺、凡例、基準commitを付ける。未コミット差分がある実行は図にも明記する。施設の地面Yは正確なアンカー座標で別途標本化し、`anchors.csv`へ記録する。

`request.json`は基準commit・未コミット差分の有無・manifestのSHA-256・入力配置・範囲と間隔、`metadata.json`は同じ基準と標本数に相当する格子サイズ・地面Y範囲・標本化時間を記録する。`sampling.log`にJava側の進捗とエラーを保存する。失敗時はそのログを確認し、修正後は別の新規出力先で再実行する。完了記録のない中間データを図として提示しない。`.bin`は24バイトのbig-endianヘッダ（magic、X0、Z0、step、横標本数、縦標本数）と、各9バイトの標本（地面Y・最上面Yはsigned short、地表材・最上面材はpaletteのunsigned short番号、flagsはbyte）からなる。flagsは1=海、2=内陸水面、4=雪、8=氷河、16=凍結水面。

全域はX/Zとも`[-16384,16384)`、北西大陸と周辺海域はX`[-16384,7168)`・Z`[-16384,1024)`。標本数は合計約1,060万列。標本化は数分、初回のコンパイル・描画込みでは数分〜十数分を見込む。Javaと描画に数GiBのメモリの余裕を持つ。間隔を半分にすると標本数は約4倍となる。表示上は地図部分の横幅を最大3072画素へ拡大するが、実データの解像度は標本間隔のまま。

出力を目で見て、海岸・水域・山脈・施設ラベルが実データと整合することを確認する。配置案は詳細版を現状確認の下図とし、淡い版に案を重ね、AGENTS.mdで指定されたGPT imageの地図と併用する。変更前後は各commit/worktreeで同じ範囲・間隔を使い、出力の基準を添える。標本間隔より細い河川・微地形は省略され得る。テクスチャ・実際の光・霧・空・建物・植生は再現せず、見た目は#85の自動撮影で確認する。画像・中間データ・キャッシュは公開対象に含めない。

## 入力の編集と由来

- `input/land.png`: 2048²の8bitラベルPNG。0=海、1=北西大陸、2=東大陸、3=南大陸、4=島嶼。色補正せず整数値で編集する。
- `input/extraction.json`: 参考図のパス、原本SHA-256、切出し座標、縮尺、抽出設定。
- `input/layout.json`: 地域ポリゴン、山脈、大河、固定シード、施設代表アンカー、経路、鉱床アンカー、未決定事項。座標はブロックX/Z。
- `input/corrections.json`: 原図のピクセル座標による手修正と、陸海の照合点。北西大陸の氷河の青い影を陸へ戻した範囲を記録する。
- `input/geology.json`: 地質プロファイルの版、上下の地層、母岩、厚さ範囲、傾斜・断層、参照した#50カタログのcommit/原本SHA-256。

参考図の±18,000ラベルは36,000四方の指定として扱う。図中の目盛文字は海岸の張出しより内側にあり、以前の画像X=294〜1160、Y=67〜916による切出しでは西の海と東大陸の一部を切っていた。修正後は海岸と外周の海を含む作図範囲X=256〜1212、Y=27〜930を32,768四方へ対応させる（32768/36000倍）。目盛文字の配置を正確なピクセル座標の基準には使わない。北は−Z、上端80°N、下端境界80°S。図の縦横差はそれぞれ2048pxへ対応させて補正する。この切出し変更も未リリース版の再生成対象。

参考図からやり直す場合だけ次を実行する。**手修正した入力PNGは上書きされる。**

```powershell
& .\tools\fixed-map\.venv\Scripts\python.exe -X utf8 tools/fixed-map/extract_mask.py
```

濃紺の海（B−R>20、B−G>6、R<80）を基準に分類し、赤い火山地形を陸として保持する。海上の文字・凡例箱・宇宙ステーション挿絵・破線・座標線は局所的に除外する。3pxのclosingとmedian、12px未満の小領域除去を行い、海峡を大きなフィルタで埋めない。閉じた内陸の穴は、地名・地形描き込みを採用しない陸海輪郭として埋める。内陸湖を参考図から引き継ぐ操作ではない。海に誤検出された内側の氷河の影だけを`corrections.json`の手描きポリゴンで戻す。除外した文字等の矩形と経路は`extraction.json`にも記録する。

`preview/reference-overlay.png`は原図に入力マスクを重ね、抽出した輪郭を桃色で示す。`preview/reference-comparison.png`は左から原図・ラベル図・重ね合わせ。これらと`preview/mask.png`を目視照合してから生成する。大陸は位置と連結成分から識別し、残る島を4へまとめる。個別の島の役割は決めない。

面積比は参考図の輪郭から実測した北西34.77%、東21.78%、南32.92%、島嶼10.54%を採用し、凡例の38/27/21/14%は使わない。承認済みマスクの記録値を`layout.json`の`area_ratio_reference`に保持し、±1ポイントの退行検査と三大陸の連結検査で輪郭の変化を検出する。実測値は`index.json`の`metrics`にも記録する。設計12の面積比の記述は別Issueで実測値に合わせるため、ここでは変更しない。

## 生成とデータ形式

#84 r4bでは、谷頭の支谷の合流位置を分け、両岸へ周囲の岩の起伏を戻す。東西に揃うノイズ・勾配の折れ、岸の奥へ伸びる水位段差、支沢の角張った距離場と山中の段丘を修正した。r4から制作資産の再生成は不要。確認図は谷頭の拡大に加えて`--bounds -4600 -11500 -4000 -11000 --step 1`でも山の出口を描き、影の直線がないことを確認する。

#84 r4では、源流の広い谷頭と制作時の広域の彫り込みを撤去した。山中の狭い渓谷は格子幅16より細いため、上流の標高PNGは山の基盤を残し、実際の河床・岸と肩は`FixedTerrain.column`が彫る。上流の水域旗と索引の水位は流路復元用であり、旗のある全格子を幅16の河床と解釈しない。源流の南650〜1,300ブロックで従来の広い谷へ接続する。水際・谷の幅と通行性はGameTestで実列を検査し、`render_map.py`では山域をstep 4、源流の拡大をstep 1〜2で確認する。生成済みの試作ワールドは新規作成する。

標高ノイズ（固定PCG64）→固定の主脈と分岐→海岸の遷移→河床の制約・施設・徒歩路の整地→priority floodによる窪地処理・集水方向/面積→地質→土壌/水域→索引、の順に処理する。全面的な侵食シミュレーションは行わない。施設のアンカー高と周囲128ブロックの移行斜面は排水解析の前提に含め、保護域と水域の重複を拒否する。

山脈の入力は`mountains`配列とし、旧単一mountain形式は扱わない。各要素はid、折れ線points（ブロックX/Z）、radius_blocks、peak_y、passesを持つ。主脈north_mainの折れ線と半径1,100は維持し、north_branchは主脈上の（−3,800, −12,020）から（−2,368, −14,992）へ半径700で接続する。峰の高さの目安は主脈520、分岐440。固定範囲内の細い主稜線と尾根型のノイズにより、峰・鞍部・不均一な支稜と谷を作る。配置図の山脈範囲は両方とも地質プロファイル3を使う。 2026-11-22のr9で東へ移し、分岐軸を全て陸上へ置く。源流は谷頭として残し、north_pathは旧分岐の峠を外して西側へ再導出する。

passesはroute・xz・surface_yを持つ。north_pathの主脈・分岐の交差点を鞍部へ下げ、A*の制約点にする。初期地点から鉱業地帯へのmining_accessとnorth_pathは、端の拠点高を固定した勾配1/8以下のwalkwaysを導出する。索引のpoints_x_z_yは[X,Z,地面Y]の配列で、地面Yは連続値。Java側はその高さを4ブロックの路面へ適用し、外側28ブロックで元の斜面へ戻す。原点や経路端の高さを探索順で変えない。生成器は地面の上の雪を含む徒歩の段差と粉雪の除外も検査する。

foothill_yは経路・河川・地域を決める旧基盤の値で、主脈130、分岐100。r19ではこれらの決定後、山脈のflanks（r17と同じ[X,Z,Y,片幅]の支稜断面）を使い、支稜の間の中腹と山すそを下げる。主脈・分岐の半径内で長さの異なる支稜と谷を作り、外側を主にY90〜130へ戻す。固定峰・西端・源流渓谷・施設を保全し、地下入口を山体へ続く支稜で支える。排水を再計算し、徒歩路はX/Zと峠・端点を固定して勾配1/8以下へ再整地する。経路探索では固定油層の周囲を避け、保護域で有限資源の中心を消さない。

r19 r2では、flanksの固定点を通る曲線と、稜線方向に変わる肩幅を使う。旧配置標高で支稜の途中を水平に切らず、固定峰・地下中心・入口と源流北の稜線を局所的に保全する。源流の保全帯は実際の流路へ沿わせ、幅を変化させる。実列側の山地起伏も回転した複数尺度へ変え、雪氷が格子状にまとまるのを避ける。主脈・分岐と問題箇所のstep2図で確認し、実列の雪氷・Y180境界の軸平行区間をGameTestで検査する。

旧分岐の2島はr14（2026-11-22）で内部の曲がる水路により5島へ分割する。最高Yは195/205/150/130/150で、固定した小峰・稜線と海から直接立つ岩岸を持つ。`mountain_islands`にid・parent_id・anchor_xz・peak_y、分割履歴`island_channels.json`に元マスクのハッシュと陸から海に変えた66画素を持つ。変更は元の2連結成分の内部だけで陸を追加しない。地質3・地域255を維持し、浜・礫浜・岩棚を作らない。索引はsummit_xz・inland_depth_blocks・pixel_spans_y_x0_x1exを生成する。Javaは島の所属を周囲32ブロックまで延ばし、滑らかな海岸線との判定のずれを避ける。

峰を作る際は既存の標高を下限とし、島内の斜面や小さな尾根を低くしない。対象島以外の高さは変更しない。

地域ポリゴンは承認緯度帯の包絡であり、その長方形を出力境界にはしない。山脈線・平滑標高・固定ノイズで座標を曲げ、農業域は大河沿い、乾燥/工業の境界は入力の分水界と標高、沿岸域は海岸から640ブロック以内を参照して形を決める。IDの形を変えるだけであり、128〜256ブロックの境界の連続化はDの担当。

大河は制約点を通るCatmull–Rom曲線に固定シードの蛇行（最大180ブロック）を加え、河床の周囲に谷を作る。水面は経路長に沿って海へ非増加となる。経路は64ブロック格子のA*で海と高度差を避け、角を二次曲線で丸める。出力索引には入力の直線ではなく、この地形を参照した折れ線を保持する。

出力先は`modules/world/src/main/resources/data/ashen_frontier/fixed_map/earth_001/`。

### 地質プロファイルとDへの契約

`geology_profiles.json`は`map_version`、`format_version=1`、`profile_version=geology_002`を持ち、manifestと索引の`geology_profile_version`に一致させる。`profiles`のキー0〜5が`geology.png`の値。全ファイルを同じmanifestのSHA-256照合対象にする。
